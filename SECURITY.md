# Security Policy

## Supported versions

Security fixes are applied to the latest published release. Please upgrade to the most recent version
before reporting an issue.

| Version | Supported |
|---------|-----------|
| latest  | yes       |
| older   | no        |

## Reporting a vulnerability

Please do not open a public issue for security problems.

Report vulnerabilities privately through GitHub:

1. Go to the repository's **Security** tab.
2. Click **Report a vulnerability** (GitHub private vulnerability reporting).
3. Describe the issue, the affected version, and steps to reproduce.

If private reporting is not enabled on this repository, ask a maintainer to enable it under
**Settings -> Code security and analysis -> Private vulnerability reporting**, or contact a maintainer
directly through the address listed on the repository owner's profile.

## What to expect

- An acknowledgement of your report, typically within a few business days.
- An assessment of the impact and affected versions.
- A fix released as a new version, with credit to the reporter unless anonymity is requested.

Thank you for helping keep this project and its users safe.

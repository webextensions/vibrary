# 015 - Docs never disclose that every agent run uses --dangerously-skip-permissions

- **Area**: keeping docs truthful to the code / aligning behavior with user expectations
- **Files**: [docs/editor.md](../editor.md), [docs/README.md](../README.md),
  [backend/utils/runClaudeApply.js](../../backend/utils/runClaudeApply.js),
  [backend/utils/runClaudeApplyBatch.js](../../backend/utils/runClaudeApplyBatch.js),
  [backend/utils/runClaudeGenerate.js](../../backend/utils/runClaudeGenerate.js),
  [backend/utils/runClaudeChat.js](../../backend/utils/runClaudeChat.js),
  [backend/utils/runClaudeRunTask.js](../../backend/utils/runClaudeRunTask.js)
- **Status**: proposed (review only - not implemented)

## Finding

All five headless agent invocations pass `--dangerously-skip-permissions` to `claude -p`:

```
backend/utils/runClaudeApply.js:      args: ['-p', prompt, ...CLAUDE_STREAM_FLAGS, '--dangerously-skip-permissions']
backend/utils/runClaudeApplyBatch.js: (same)
backend/utils/runClaudeGenerate.js:   (same)
backend/utils/runClaudeChat.js:       (same)
backend/utils/runClaudeRunTask.js:    (same)
```

That flag removes every permission gate the Claude CLI normally applies: the agent can run arbitrary shell commands,
edit or delete any file it can reach, and make network calls, without ever pausing for approval. For this app it is
arguably the right default - a permission prompt has no way to reach the browser UI, so a gated run would just hang -
but it is a significant trust decision made on the user's behalf, and the documentation never mentions it:

- `docs/editor.md` describes "Apply this spec" / "Run this task" / "Create entries with AI" only as "headless-agent
  run" actions that "edit files directly" or "append entries".
- `docs/README.md` says nothing about agent runs at all.
- `grep -rn dangerously docs/` finds nothing; the flag exists only in the five backend call sites.

A user who runs `vibrary-server` in a folder and clicks "Run this task" on a task written by someone else (or
generated by a previous AI run) has no documented way to know the agent executes with all safety prompts disabled.
The mismatch between what a reasonably cautious user assumes ("it edits files in this folder") and what the flag
allows ("it can run any command as me") is exactly the kind of claim docs exist to make truthful.

## Suggested improvement

- Add a short, prominent paragraph to `docs/README.md` (and a sentence in `docs/editor.md` where the run actions are
  introduced): agent actions run the Claude CLI with permission prompts disabled
  (`--dangerously-skip-permissions`), meaning the agent can execute commands and edit files without asking; only run
  vibrary in folders and on entries you trust.
- Optionally note the existing mitigations in the same place so the risk statement is balanced: runs are killed on
  cancel/refresh (process-group SIGTERM), and each run's full prompt is visible in the Activity monitor.
- A code comment on `CLAUDE_STREAM_FLAGS`' neighbors in `spawnClaude.js` (or wherever the flag is centralized, if it
  ever is) explaining WHY skipping permissions is required would keep the decision reviewable; today the flag appears
  five times with no rationale anywhere.

## Verification

- Docs-only change; `node --run lint` (covers nothing here) and a proofread suffice.
- Confirm the wording matches actual behavior: the flag is present on all five call sites, and no run has any
  permission-prompt path.

## Risk

None to runtime. The only consideration is wording: state the behavior plainly without overpromising sandboxing that
does not exist.

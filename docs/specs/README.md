# Specs

Pre-implementation design docs for non-trivial changes: problem, scope, approach, verification.
One file per spec, named as a kebab-case `<short-slug>.md`. A spec is a point-in-time plan, not
living documentation - once implemented, the code and configs are the source of truth.

- [todo/](./todo/) - pending work: the `TODO.md` / `TODO-for-<branch>.md` task lists and specs not
  yet implemented.
- [implemented/](./implemented/) - specs whose implementation is done (kept for the record).
